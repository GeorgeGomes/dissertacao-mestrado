Algoritmo 1: Perceptron Estruturado com Relaxação de Margem

Texto do orientador

Entrada: Dados {(v(i), y(i)), v(i) ∈ R², y(i) ∈ {0,1}, i = 1..n}
         e centróides c(1) e c(2)
         Parâmetros: η, γ, λ, T
         Vetor primal w ∈ R²₊, vetor dual α ∈ Rⁿ₊
Saída:   w*, α*, número de iterações t
Início
  stop ← F; t ← 0;
  Enquanto (t ≤ T) ∧ (¬stop) Faça
    stop ← V;
    Para i ← 1 até n Faça
      ŷ(i) ← Arg Min_{k∈{1,2}} d_w(v(i), c(k));
      Se y(i) ≠ ŷ(i) Então
        Se (d_w(v(i),c(ŷ(i))) − d_w(v(i),c(y(i))) + λα_i) < γ‖w‖ Então
          stop ← F;
          w ← Max{0, w(1 − ηγ/‖w‖) + η(d_I(v(i),c(ŷ(i))) − d_I(v(i),c(y(i))))};
          α ← α(1 − ηγ/‖w‖);
          α_i ← α_i + η;
        Fim_Se;
      Fim_Se;
    Fim_Para;
    t ← t + 1;
  Fim_Enquanto;
  Retorne w;
Fim.

Proposta

Entrada: Dados {(v(i), y(i)), v(i) ∈ R², y(i) ∈ {0,1}, i = 1..n}
         e centróides c(1) e c(2)
         Parâmetros: η, γ, λ, T
         Vetor primal w ∈ R²₊, vetor dual α ∈ Rⁿ₊
Saída:   w*, α*, t, viável ∈ {V,F}, w_me (melhor esforço), e_me
Início
  stop ← F; t ← 0; e_me ← ∞;
  Enquanto (t ≤ T) ∧ (¬stop) Faça
    stop ← V; erros ← 0;
    Para i ← 1 até n Faça
      ŷ(i) ← Arg Min_{k∈{1,2}} d_w(v(i), c(k));
      k ← rival de y(i)  (o outro centróide)
      Δ_i ← d_w(v(i),c(k)) − d_w(v(i),c(y(i)));      margem bruta, sem αA
      Se Δ_i < γ‖w‖ Então stop ← F; Fim_Se;            viabilidade pela margem bruta
      Se y(i) ≠ ŷ(i) Então erros ← erros + 1; Fim_Se;
      Se (Δ_i + λα_i) < γ‖w‖ Então                      correção com a folga, para qualquer ponto1
        w ← Max{0, w(1 − ηγ/‖w‖) + η(d_I(v(i),c(k)) − d_I(v(i),c(y(i))))};
        α ← α(1 − ηγ/‖w‖);
        α_i ← α_i + η;
      Fim_Se;
    Fim_Para;
    w ← w/‖w‖; α ← α/‖w‖;                               escala fixa, mesma direçãoB
    Se erros < e_me Então w_me ← w; e_me ← erros; Fim_Se;C
    t ← t + 1;
  Fim_Enquanto;
  viável ← stop;                                       V só se Δ_i ≥ γ‖w‖ para todo i
  Retorne w, α, t, viável, w_me, e_me;
Fim.
A · Dois testes com papéis diferentes. No texto, a mesma desigualdade (com λα_i) decide duas coisas: se o ponto corrige w e se a margem foi alcançada (stop). Na proposta, a correção continua usando a folga, mas o stop passa a depender só da margem bruta Δ_i. É isso que impede o algoritmo de "parar com sucesso" quando w encolheu e a folga está cobrindo pontos do lado errado.
B · Normalização por época. O fator (1 − ηγ/‖w‖) encolhe w a cada correção; com w pequeno a exigência γ‖w‖ some. Dividir w e α por ‖w‖ ao fim de cada época preserva a direção (a única coisa que a regra do centróide mais próximo usa) e mantém a exigência de margem com tamanho fixo.
C · Melhor esforço explícito. O texto não diz o que devolver quando nenhum γ é viável. O código já devolvia um "melhor esforço", mas escolhido pela época com menos violações com folga, o que premia as épocas em que w evaporou. A proposta guarda w_me, o w da época com menos pontos mal classificados.
1 · Já era assim no código. O texto só corrige quando y(i) ≠ ŷ(i) e a margem relaxada falha; o código corrige qualquer ponto cuja margem relaxada falhe, mesmo bem classificado (é o Perceptron de margem do CILAMCE 2017). Mantive o comportamento do código; a revisão de 15/10 mostrou que a variante do texto colapsa ainda mais (w = [0, 0]). Fica para o senhor decidir qual das duas vai para o texto.

Algoritmo 2: estratégia incremental com pesquisa binária

Texto do orientador

Entrada: fator de incremento da margem Δ, máximo de iterações T,
         tolerância ε
Saída:   w* ∈ R²₊
Início
  γ ← 0; t ← 0; w* ← [1,1]; α* ← 0;
  Enquanto t ≤ T Faça
    w ← w*; α ← α*;
    Algoritmo1(γ, t, w, α);
    Se t ≤ T Então            terminou antes do limite = viável
      γ_ini ← γ; w* ← w; α* ← α;
      γ ← γ · Δ;
    Senão
      γ_fim ← γ;
    Fim_Se;
  Fim_Enquanto;
  Enquanto (γ_fim − γ_ini) > ε Faça
    γ ← (γ_ini + γ_fim)/2;
    w ← w*; α ← α*;
    Algoritmo1(γ, t, w, α);
    Se t > T Então γ_fim ← γ Senão γ_ini ← γ Fim_Se;
    w* ← w; α* ← α;
  Fim_Enquanto;
  Retorne w*, α*;
Fim.

Proposta

Entrada: incremento da margem δ, máximo de iterações T,
         tolerância ε
Saída:   w* ∈ R²₊, γ*, viável, margem_mínima
Início
  γ ← γ₀ (0,1); t ← 0; w* ← [1,1]; α* ← 0; viável_alguma ← F;2
  Enquanto t ≤ T Faça
    w ← w*; α ← α*;
    (w, α, _, viável, w_me, e_me) ← Algoritmo1(γ, w, α);
    guardar w_me se e_me for o menor até agora;               melhor esforço globalC
    Se viável Então                margem bruta ≥ γ‖w‖ em todos os pontosA
      γ_ini ← γ; w* ← w; α* ← α; viável_alguma ← V;
      γ ← γ + δ (ou o ponto médio se γ_fim já for conhecido);2
    Senão
      γ_fim ← γ;
      γ ← (γ_ini + γ_fim)/2; w ← w*; α ← α*;         bisseção já aqui3
    Fim_Se;
    Se (γ_fim − γ_ini) ≤ ε Então sair; Fim_Se;
  Fim_Enquanto;
  margem_mínima ← min_i Δ_i / ‖w*‖;                          gravada no CSVD
  Se viável_alguma Então Retorne w*, γ_ini, V, margem_mínima;
  Senão Retorne w_me, 0, F, margem_mínima;                  melhor esforço, marcado com †
Fim.
A · "Viável" vem do Algoritmo 1 novo. No texto a viabilidade é "o Algoritmo 1 terminou antes de T", e ele termina quando a margem relaxada passa para todos. Na proposta termina quando a margem bruta passa para todos; o resto da busca é igual.
D · Diagnóstico. Além de γ, o CSV ganha a margem mínima bruta dividida por ‖w*‖. Negativa significa que a régua devolvida não separa os rótulos, e as tabelas marcam † nesses casos e no melhor esforço.
2 · Já era assim no código. O texto parte de γ = 0 e multiplica por Δ; o código parte de γ₀ = 0,1 e soma δ = 0,05. Não proponho mudar isso agora; é uma diferença a registrar no texto.
3 · Já era assim no código. O texto faz a fase incremental inteira e só depois a bisseção; o código entra na bisseção no primeiro γ inviável e restaura w* (o texto guarda w mesmo quando inviável). O código é o mais defensável aqui; diferença a registrar no texto.
